# Owner routing decision — recurrent retrieval pilot

On November 17, 2026, after reviewing completed Study D0–D2, the owner explicitly
agreed to the proposed next recurrent-retrieval experiment and requested publication
of the D article. This selects one fresh direction for protocol design through
[SOAM-086](../../tickets/SOAM-086-recurrent-retrieval-protocol.md). It does not change
the frozen D decision or automatically activate another study.

The owner's reason is broader than replacing nearest-neighbor lookup. If retrieval
and tracking can use a similar recurrent computational substrate, a later system
might learn or discover which populations serve as memory, which track dynamics,
and how their connections and gates should adapt. The long-term motivation is
scalability and adaptability through learned organization. The present pilot tests
a component prerequisite; manually assigning a recurrent memory role would not
demonstrate self-organization or a scaling advantage.

The bounded next question is whether a competent iterative associative memory can
acquire, recover after reset, and retain associations while using the fixed action
core and strong explicit-memory/direct-read controls. Full versus partial cues and
settling interventions should distinguish stored-map damage from failed completion.
The concrete model, learning rule, endpoints, budgets, splits and stopping criteria
belong to the new protocol, not this routing record.

Original D2 tests sequential retention. Original D3 tests bad measurements, wrong
correspondence and changed relationships; D4 tests fixed-capacity load. The new
mechanism pilot may reuse D1/D2 questions but is not D3 or a retroactive D amendment.
D3/D4, E0, bidirectional population coupling, learned role discovery and broad
topology/scaling searches remain deferred. The previous D budget was scoped to
D0–D2; a new numerical allocation must be declared before the new trials.
