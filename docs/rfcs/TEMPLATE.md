# RFC: bounded decision title

Owner ticket: SOAM-XXX. Status: draft / accepted for experiment / superseded.
Date/version: YYYY-MM-DD, vN. Classification: essential next / parallel / future.

## Problem and hypothesis

What behavior or failure motivates this decision? Link the operational hypothesis,
existing evidence, and unchanged historical claims. What would falsify this choice?

## Prior research and alternatives

Cite the relevant primary mechanism and limits. Compare a simpler conventional
reference and an unconventional or hybrid alternative where relevant. Explain why
this experiment, rather than a complete architecture, is needed now.

## Proposed mechanism and boundaries

Specify state, parameters, observations, actions, time/update equations, learning
rule, readouts, and ownership. Mark supplied/fitted/learned structure, privileged
inputs, external storage, and unsupported theoretical assumptions.

## Evaluation and trade-offs

Link one authoritative numerical manifest: primary endpoint, effect margin,
guardrails, seeds/splits, controls, exposure/capacity/compute caps, stopping and
inconclusive rules. Explain confounds, uncertainty, costs, and what each outcome means.

## Dependencies and implementation

Name exact ticket IDs and affected interfaces. Identify the minimum implementation,
required invariant tests, deferred features, and any migration from an old contract.

## Decision and revision trigger

Record rationale, unresolved assumptions, selected experiment, deferred alternatives,
and proceed/revise/stop in the owning ticket. State what evidence would require a
new version or alternative mechanism. This is not an empirical gate pass.
