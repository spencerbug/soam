# SOAM-041: Review rapid acquisition and retained generalization

## Recommended thinking

**high** — Evaluate acquisition and protection together and separate this empirical gate from the preceding design decision.

## Problem / hypothesis

Successful switching or an approved learning design does not establish persistent useful learning.

Specification: [SOAM v0.3](../docs/RESEARCH_SPEC_V0_3.md).
Apply the [common completion requirements](README.md#completion-requirements).

## Scope

- Review E2 acquisition, retention, reset persistence, one-exposure evidence and complete resource accounting against frozen criteria.
- Decide which learning mechanism, if any, deserves a further bounded sensorimotor test; keep single-shot recall, few-shot adaptation and compositional transfer separate.

## Acceptance criteria

- [ ] Record proceed/revise/stop with exact evidence and supported conditions; a candidate advantage requires held-out acquisition and retention criteria, not only the written transition.
- [ ] Keep one-shot conclusions separate from broader acquisition: a passing few-observation curve does not establish one-shot learning.
- [ ] If only a conventional or retrieval reference works, retain that evidence and revise the candidate claim; do not call it shared recurrent learning.
- [ ] State whether harmful writes motivate one credit/constraint or fast-memory/core diagnostic; no automatic learned scope or consolidation.
- [ ] Authorize only the selected supported follow-up, with later organization/composition/integration gates intact.

## Metrics / evidence

Expected report: reports/SHARED_POPULATION_ACQUISITION_GATE.md with exact report/artifact references and outstanding learning failures.

## Dependencies

## Branch conditions

The prior skill/concurrency requirements are no longer prerequisites for E2. A proceed supplies narrow acquisition evidence, not validated multi-instance binding or full architecture readiness. Revise/stop keeps dependent organization and module work unready; a new evidence-based routing/protocol decision can test an alternative without rewriting this outcome.
